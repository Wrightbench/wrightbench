# AGENTS.md — Wrightbench

Instructions for AI agents (and humans) working in this repository. Read this before touching code.

## What this is

**Wrightbench** is a desktop studio for recording, running, debugging and reviewing Playwright test suites. The Electron app brings Playwright's scattered tools — codegen, UI Mode, trace viewer and HTML reports — into one workspace, with multi-project management, persistent run history and flakiness analytics.

## Source of truth (read this first, every time)

1. **`design_handoff_wrightbench/README.md`** — theme token table, type/spacing/radii scales, per-screen specs, interactions, state model. This is the contract.
2. **`design_handoff_wrightbench/Wrightbench.dc.html`** — the pixel reference: 20 inline-styled 1440×900 artboards (`<div data-screen-label="01 Welcome light">` … `"12D Traces Dark"`). When the README and your instinct disagree, **grep this file and use the exact inline value**. Lines are extremely long — use `sed -n 'N,Mp' file | fold -w 160` or a Python `re` one-liner, not naive reads.
3. **Never copy the handoff HTML into the app.** It is a reference to recreate in React components, not production code. `support.js` is only the artboard viewer runtime — ignore it entirely.

## Stack

- **Electron + electron-vite + React + TypeScript** (strict). `electron-builder` for packaging.
- **State:** Zustand for UI state (renderer); **SQLite via better-sqlite3 in the main process** for run history (`~/.wrightbench/history.db`, WAL). It is built for Electron's ABI — after any `npm install` run `npx electron-rebuild -f -w better-sqlite3`. To unit-test db.ts under plain node: `npm rebuild better-sqlite3` first, then rebuild for Electron. Keep it out of the renderer.
- **IPC:** typed contextBridge channels only. The whole contract lives in `src/shared/ipc.ts` — add the channel type there first, then implement both sides. Never call `ipcRenderer` outside `src/preload/`.
- **Styling:** CSS custom properties + CSS Modules. **No Tailwind. No component library.** The design system is bespoke and small.
- **Playwright integration** runs in the main process: spawn `npx playwright test` with a custom JSON/event reporter; host UI Mode / Trace Viewer / HTML report in `<webview>` tags pointed at their local server ports. **Never rebuild Playwright's own UIs — frame them in webviews.**
- **Supported project Playwright:** new workspaces must resolve a project-local Playwright `>=1.56.0 <2.0.0`; `1.62.1` is the latest verified release. The canonical policy and scaffold catalog live in `src/shared/playwright-compat.ts`. Import and Record use the compatibility range; Create offers the exact latest patches from five verified minor lines (`1.62.1` through `1.58.2`) plus explicitly experimental `latest`/`next` aliases, defaulting to the newest verified release. Missing, older, malformed, and future-major installations must never be persisted through import. Browser binaries do not gate import.

## Layout

```
src/main/       Electron main process (window, theme, settings; later: run spawning, SQLite)
src/preload/    contextBridge only — exposes window.wrightbench (typed by src/shared/ipc.ts)
src/shared/     types shared across processes (IPC contract lives here)
src/renderer/   React app
  src/components/   shared primitives (one folder per component: Foo.tsx + Foo.module.css)
  src/kitchen-sink/ every primitive rendered in both themes (dev verification surface)
  src/state/        Zustand stores
  src/styles/       tokens.css (theme tokens), base.css, fonts.css
```

## Commands

```bash
npm run dev        # electron-vite dev — launches the Electron app with HMR
npm run typecheck  # tsc over main+preload and renderer projects
npm run build      # electron-vite production build to out/
npm run package    # build + electron-builder --dir (unpacked .app in release/)
```

The renderer dev server URL printed by `npm run dev` also opens in a plain browser — useful for quick kitchen-sink checks (Electron-only APIs are behind `window.wrightbench?`, which is undefined there and must stay optional-chained).

## Design-system rules (non-negotiable)

- **Tokens only.** Colors come from the CSS variables in `src/renderer/src/styles/tokens.css` (`--bg --panel --card --active-row --bd --t1 --t2 --t3`, brand/interaction, status, tint, and hosted-surface sets). Raw hex in a component is a bug except for native macOS traffic lights and deliberately fixed media pixels such as the white snapshot scrubber handle. `WebviewFrame` and the Report/Trace placeholders use theme-scoped `--wv-*` tokens that mirror Playwright's light/dark surfaces; UI Mode itself remains frameless. Values the reference deliberately theme-shifts are already split into tokens (for example `--ac` / `--ac-icon` are `#2ead33` light and `#45ba4b` dark). If you find a new one, add a token — don't inline it.
- **Brand lockup:** the welcome titlebar is borderless and carries no product label; branding lives in the hero. The canonical Wrightbench logo is the fixed-color angular `WB` monogram and outline on a `#24313a` rounded triangular badge with a transparent outer canvas; its `#248a2b` mark and navy badge are identical in both themes, while the separate text wordmark remains theme-adaptive through `--brand-wordmark`. The native app/dock logo source is `resources/icon.svg`; keep the generated transparent 1024px `resources/icon.png` synchronized when that source changes.
- **Both themes on every screen from day one.** Never a light-only component. Theme = `data-theme="light|dark"` attribute; tokens are defined on `[data-theme]` (not `:root`) so any subtree can be re-themed — the kitchen sink relies on this. Light/Dark/System, with System following `nativeTheme` in the main process.
- **Type:** Schibsted Grotesk 400/500/600 for all UI; Source Serif 4 600 only for display moments (welcome headline 36px, Settings section titles 17px); JetBrains Mono 400/500 for code, paths, durations, commit hashes, run numbers. Base 13.5px/1.5; tables/trees 12–12.5px; status bar 11.5px; micro-labels 10.5px/600 with .09em letter-spacing. Fonts are bundled via `@fontsource/*` — never hotlink.
- **Radii:** 14 window · 10–12 panels/cards · 8 controls · 7 list rows · 999 pills.
- **Shadows:** near-none — 1px border + the theme-scoped `--card-shadow` token only.
- **Icons:** inline stroke SVGs, 1.5px stroke, round caps/joins, 11–15px, via the `Icon` component registry. Paths are lifted verbatim from the reference HTML. No emoji, no gradients, no icon fonts.
- **Interactions:** rows hover-tint to `--panel`; selected rows use neutral `--active-row` plus a green edge/icon; primary buttons move to `--ac-hover`; focus = 2px `--ac` ring. Status dots: 7px filled (pass/fail/flaky), 7px hollow 1.5px-border queued, 12px green accent spinner (1s linear) running.
- When unsure about **any** value, grep the artboard. Do not invent, round, or eyeball.

## Process rules

- Record's project-local adapter must support both the modular `playwright-core/lib/server/*.js` layout used by Playwright 1.56 and the consolidated `playwright-core/lib/coreBundle.js` layout verified in 1.62. The bundled path may expose only the narrow Recorder symbols needed by Wrightbench and only in memory; it must never rewrite project files or the exact Inspector assets served from `lib/vite/recorder`.
- Project-switch recovery copy for Record is exactly **"Recording is active. End the session to switch projects."** with a full-width, fail-tinted **End session** action beneath it. The action uses Record's canonical clean stop, remains in place as **Ending session…**, and leaves the project menu open after stopping.

- Work one phase per PR. Commit messages: imperative, scoped (`phase0: add StatusDot spinner`).
- Do not add dependencies without checking they're needed — the app should stay lean. Anything native (better-sqlite3) lives in the main process and gets rebuilt for Electron's ABI via electron-builder.
- Main process code never imports from `src/renderer`; renderer never imports from `src/main`. Shared types go in `src/shared`.
- Run lifecycle, file watching (chokidar), and process spawning are main-process concerns exposed over the typed IPC contract.
- **Harness targets** ([src/main/targets/](src/main/targets/)): a Wrightbench *workspace* (the imported folder — possibly a monorepo root) holds one or more *harness targets* (persisted per project in projects.json: cwd, config path, package root, launcher, script env/args), each a concrete Playwright invocation context; Playwright *projects* (chromium/setup/…) live inside a target's config. Non-script targets are complete **configurations**; safe script targets are optional CLI **run recipes** grouped by `(cwd, configPath, packageDir)`. Project-only and headed/debug-only aliases collapse into the base configuration. **Import is passive and configuration-only:** `inspect.ts` calls `discoverTargets(..., { validate:false })`, never loads configs or tests, never probes browser caches or Node, hides recipes, and shows only canonical configuration context plus the locally installed Playwright version. It caches the complete scan so `projects:add` still persists trusted targets; a cache miss repeats the same passive scan. Initial registration requires the selected base configuration to resolve a supported project-local Playwright installation (`>=1.56.0 <2.0.0`): the renderer blocks the CTA and offers **Retry detection**, while `projects:add` independently resolves the installed version and applies `src/shared/playwright-compat.ts` before persisting, so stale or forged renderer state cannot bypass the gate. Browser binaries never gate import. Existing registered projects are not removed if dependencies later disappear or become incompatible; their launch/retry surface remains recoverable. The workspace tree later uses the same target service’s authoritative list path (`targets/service.ts` → `targets/list.ts`), invoking the project’s installed Playwright directly (`node <resolved @playwright/test>/cli.js test --list --reporter=json`, structured argv, capped output, never `npx`, never a download). The test list is whatever Playwright reports—no filesystem globbing; successful tree paths are relative to the report's resolved `rootDir` inside the workspace (outside roots are explicitly unsupported), and declarations keep line/column/titlePath. Configured and post-filter project names remain separate. Passive scanning (`targets/scan.ts`) never executes package scripts or follows symlinks outside the canonical workspace boundary; `targets/script.ts` lexically adopts only plain `[env] [cross-env] [npx|yarn|pnpm|bun] playwright test …` forms with quote-aware shell-operator detection. Workspace discovery outcomes are structured statuses (`ready/empty/needs-context/dependencies-missing/…` + TargetDiagnostic), never bare strings. Wrightbench never runs arbitrary build/setup commands. Legacy projects.json entries are normalized idempotently at startup. CLI runs send only a target id; `run:start` resolves the registered target server-side and [runner.ts](src/main/runner.ts) uses its canonical cwd/config/env/argv. Target-affecting filesystem events are serialized as rescan then relist. Tests: `tests/targets.test.mjs` and `tests/targets-live.test.mjs`.
- All spawning goes through `src/main/proc.ts` (`trackedSpawn`) — it kills whole process groups on timeout/quit and handles the Windows `npx.cmd` names. Never call `child_process.spawn` directly.
- Persistent state (settings.json, projects.json — and the Phase 3 SQLite db) lives in `~/.wrightbench/`, written via `writeJsonAtomic`. The detection-card footnote promises "Adding this project won't change its files" — keep it true.
- Project scaffolding accepts only a value from the shared catalog, validates it again in the main process before writing files, and installs `@playwright/test@<selection>` with `npm install --save-dev --save-exact`. The five exact versions are a manually maintained compatibility matrix; update them only after verification. `latest` and `next` are opt-in experimental moving aliases and must stay visibly labeled as such.
- Known gap: scaffolding has no cancel IPC; cancelling in the UI abandons its main-process `npm install` (runs to completion). Browser installation is not a Wrightbench workflow. Test runs DO stop properly (`run:stop` → SIGINT to the process group → Playwright reports `interrupted`; SIGKILL escalation after 5s).
- Run engine: the custom reporter ([reporter.ts](src/main/reporter.ts)) is plain CJS written to `~/.wrightbench/reporter.cjs` and loaded with `--reporter=<path>`; it emits `WBEVT `-prefixed NDJSON on stdout which [runner.ts](src/main/runner.ts) parses and forwards as `run:event`. Live renderer identity uses target + file/line/column/titlePath; SQLite history retains the legacy testDir-relative `file:line:title` key. Focused clicks run `file:line:column` with an escaped title suffix so same-line declarations do not fan out. Errors are stored display-ready (ANSI stripped, `Call log:` dropped, `at file:line:col` appended). The runner owns reporter/config/evidence flags, keeps them before a recipe's custom `--` argv contract, and applies the Settings capture policy (`on` for Full evidence, focused-run trace in Balanced, failure trace otherwise), deliberately overriding the project's own capture mode when required by that policy.
- Failure evidence: the former Wrightbench-owned Failure Detail renderer and its custom trace parser were removed. Error-banner actions, failed/flaky history dots, and the test-row quick action now select the exact recorded run and open its embedded native Trace Viewer tab. Keep trace evidence access on that hosted Playwright surface; do not recreate a separate failure-analysis screen.
- UI Mode / trace viewer / reports are hosted Playwright servers embedded via `<webview>` — never rebuild their UIs. UI Mode runs the server-only `npx playwright test-server` (never `test --ui-port`, which also opens the system browser); [uimode.ts](src/main/uimode.ts) parses the `Listening on ws://…` stdout line and hands the renderer the full `trace/uiMode.html?ws=…` URL. Startup stderr is redacted and retained within a strict bound; recovery selects a real error headline (or the last meaningful non-boilerplate line), never a trailing runtime banner such as `Node.js v…`. One UI Mode *session* per project starts on demand when Run first opens and remains mounted across Record, Run, Report, and Settings switches. Inactive surfaces hide only with `visibility`; destination navigation must never call the guest's `reload()` because that erases Playwright-owned filters, selections, watch state, timeline, and inspector context. Genuine guest/server failures use the explicit Retry/Restart path. The session stops only on project switch, explicit restart/stop, app quit, or before a Tests/CLI run starts. Execution ownership is exclusive per project: an active UI Mode run blocks the Tests runner; otherwise starting a Tests run first drains and stops the idle UI Mode session so the two Playwright processes cannot race project artifacts.
- Environment ownership: Wrightbench does not render, select, or inject stored environment profiles for discovery, Run and Capture, or UI Mode. The Playwright project owns environment resolution through its config, `.env` loading/setup code, inherited shell, and safe fixed recipe env. Legacy `envProfiles`, `defaultProfile`, and per-project `envProfile` settings remain dormant compatibility data and must not be silently deleted during unrelated settings writes.
- UI Mode history recording: the test server is spawned with `PW_TEST_REPORTER=~/.wrightbench/reporter.cjs` plus `WRIGHTBENCH_UI_EVENTS_FILE`/`WRIGHTBENCH_UI_SESSION_ID`, so runs started inside Playwright's own UI load our reporter, which appends v1 NDJSON to `~/.wrightbench/ui-events/<sessionId>.ndjson` (UI Mode intercepts process stdout, so the stdout WBEVT transport is UNUSABLE there — never rely on it). [uisession.ts](src/main/uisession.ts) tails that file and writes normal history rows (trigger `ui-mode`, same createRun/finishRunRecord + [aggregate.ts](src/main/aggregate.ts) semantics as the CLI runner); discovery/listTests never instantiates the reporter, so only real runs create rows. Everything Playwright-private (env names, supported-version gate ≥1.44 <2, wire validation with size caps) lives in [pwadapter.ts](src/main/pwadapter.ts); recording fails open — unsupported versions still get a working embedded UI with a "recording not supported" notice. Never scrape UI Mode's DOM, inject CSS/JS into it, or open a second client on its ws endpoint. Tests: `npm run test:uimode` (isolated-HOME unit/ingest) and `npm run test:uimode:live` (end-to-end against `~/Downloads/demo`, needs network).
- Phase 5 hosted surfaces: [report.ts](src/main/report.ts) serves the last run's HTML report via `npx playwright show-report --port` (the runner passes `--reporter=html,<ours>` with `PLAYWRIGHT_HTML_OPEN=never`); [traceserve.ts](src/main/traceserve.ts) is our own tiny static server replicating show-trace's two routes (`/trace/<asset>` from the project's `playwright-core/lib/vite/traceViewer` bundle + `/trace/file?path=`), so the viewer version always matches the project. Record is implemented by [codegen.ts](src/main/codegen.ts) plus [codegenhost.ts](src/main/codegenhost.ts): the selected project's Node runtime loads its project-local Playwright, launches the selected genuine browser headed, instantiates Playwright's Recorder backend, and serves that same installation's exact `playwright-core/lib/vite/recorder` frontend files unmodified on loopback. Wrightbench embeds only that Inspector frontend; the browser remains Playwright-owned and external because Electron cannot adopt another process's native window. The explicit **Start recording** action performs one best-effort focus handoff to the newly created inspected page before navigation; Inspector readiness, state replay, destination changes, and session restoration must never repeat that handoff or steal focus later. Focus failure is non-fatal. Chromium Record launches with `--start-maximized` plus the project-local server's `noDefaultViewport` context option; after an explicit best-effort maximize and a short native settle, the host measures `window.innerWidth`/`window.innerHeight` and gives only that measured value to the generator so copied tests keep a deterministic fixed viewport. Measurement failure and non-Chromium engines retain the bounded fixed viewport; `noDefaultViewport` must never be combined with `deviceScaleFactor`. The Record destination and launcher use the filled recorder-dot icon, and the launcher headline is **Record with Codegen**. Before launch, Record contains only a centered initial URL field and **Start recording**; after launch, the Inspector owns the full canvas and Wrightbench must not add a toolbar, Restart, URL/status, or browser-selection controls around it. The one permitted surrounding action is global **End session** in the titlebar: it calls the clean stop path, closes the headed browser, and returns to the launcher; Playwright's native **Stop Recording** only changes recorder mode. A trusted sandboxed preload relays the Inspector's native protocol through bounded, method-validated IPC — never renderer-provided scripts, package paths, or argv. The host detects the transport contract from the exact frontend bundle: Playwright 1.56 uses `dispatch({ event })` plus named `playwrightSet*` receivers, while newer frontends use `sendCommand({ method })` plus `dispatch({ method })`; do not assume one contract across supported versions. The private adapter is isolated in generated `~/.wrightbench/record-host.cjs` and version-gated to verified Playwright ≥1.56 <2; unsupported versions fail closed without affecting UI Mode. Never scrape, restyle, or recreate the Inspector. Missing browser binaries surface the exact `npx playwright install <browser>` remedy. All per-project servers/sessions stop on project switch and quit. Unit coverage runs inside `npm run test:uimode`; set `WRIGHTBENCH_RECORD_PROJECT=<Playwright project>` and run `npm run test:uimode:live` for both the host protocol test and the full Electron guest-bridge test.
- Record's clean shutdown is version-adapted: modular Playwright uses server `Browser.close(options)`, while the consolidated server bundle uses `Browser.close(progress, options)`. Once **End session** is requested, late host/process diagnostics from teardown must not replace the clean stopped state with a Record failure.
- The workspace titlebar has one stable structure across all three destinations: macOS window controls then the project selector on the left, direct **Record | Run | Report** navigation mathematically centered at every supported window width, and contextual session actions plus the Settings utility on the right. Keep balanced left/right grid tracks; never switch the navigation to intrinsic placement at narrow widths. **Run** is the product label for the embedded Playwright UI Mode destination; Playwright-specific status, recovery, and lifecycle copy still says UI Mode. **Report** is the product label for the report/history destination. Never render a separate static project/configuration label for UI Mode. While Record owns a headed browser (starting, ready, or stopping), its existing filled recorder-dot icon becomes `--fail` red with a subtle pulse in every destination and Settings; the treatment must not change tab dimensions, its accessible name announces "recording in progress," and reduced-motion users receive a static ring. The project menu must escape the left grid cell, open below the full titlebar, and align to the selector's left edge so it never overlaps the native macOS window controls. When work blocks switching, its note must name Record, the test run, or UI Mode rather than saying only "active session." An active Record lock also exposes the same clean fail-tinted **End session** action beneath the note; it remains in place as **Ending session…** and leaves the project menu open after stopping so switching is immediate. Destination clicks are idempotent, never back/toggle controls; any choice closes the Settings overlay and shows the requested destination. Active Record and UI Mode sessions stay alive while their surface is hidden, preserving the headed browser/native Inspector and Playwright UI Mode webview state; Report preserves its local drill-down/filter/scroll state. Settings is not a peer destination: it overlays the active destination and has an explicit **Back to Record/Run/Report** action; its quiet full-window variant is reserved for import recovery before a workspace exists. Live UI Mode Restart/Stop actions are consolidated under one status trigger (`UI Mode ready`, starting/restarting, or run progress) in the right control cluster; Restart keeps its existing safety gates and Stop remains available in the menu. Settings is one responsive page: do not render an internal category sidebar until multiple real Settings pages exist; center the two desktop columns and stack them below 1100px. Settings keeps its own save/version status bar and persists through `settings:get`/`settings:update` (theme still flows via `theme:set`); density stamps `data-density` on `<html>` (compact tightens only tables/tree rows via `:global` rules), code font overrides `--font-mono` inline; `nodeMode: fixed` prepends `dirname(nodePath)` to run PATH; "Clear old artifacts" prunes db rows only — repo files are never deleted.
